# 设计有AI：公开公众号链接 → 个人网站

当前采用公开文章链接归档，不需要 Markdown 源稿、浏览器插件或公众号 AppSecret。

## 当前流程

1. 从用户提供的公开文章链接打开微信原文，核对公众号名称与正文。
2. 使用页面实际展示的合集目录、上一篇和下一篇发现其他文章，不猜测文章 ID，也不访问后台内部接口。
3. 逐篇读取标题、作者、完整发布日期、摘要、原始封面和正文 HTML，保存浏览器读取结果。
4. 对账号不匹配、日期缺失、作者设为私密、删文或微信验证页面停止该篇导入。环境验证或限流时停止采集，等待用户正常处理；不切换账号或代理绕过。
5. 运行导入脚本，清理正文、将配图存到网站、按来源和发表时间复用原页面路径。
6. 构建、检查页面和图片后，提交并部署 GitHub Pages。

本次从用户文章链接的“热点资讯”合集向前、向后读取，共发现 21 个条目，其中 16 篇有公开正文，5 篇显示“根据作者隐私设置，无法查看该内容”。合集可见文章日期范围为 2026-06-12 至 2026-09-05。这个合集不等于公众号的全部历史文章。

公开来源记录在 `src/data/wechat-source.json`，文章数据在 `src/data/wechat.json`。本地核验报告 `output/wechat/public-directory-audit.json` 记录发现条目和不可访问原因，不随网站发布。

## 导入命令

浏览器采集结果放在一个本地文件夹，每篇一个 JSON。用户只需要提供链接，这些文件由读取流程生成，不要求用户准备。

```powershell
npm run sync:wechat -- --capture-dir tmp/wechat-captures
npm run test:wechat
npm run build
```

捕获格式：

```json
{
  "account": "设计有AI",
  "title": "已发表文章标题",
  "author": "作者",
  "publishedLabel": "2026年6月23日 08:30",
  "sourceUrl": "https://mp.weixin.qq.com/s/真实文章ID",
  "excerpt": "原文摘要",
  "cover": "",
  "contentHtml": "<p>页面中的公开正文</p>"
}
```

日期使用页面实际显示的中国标准时间。只从标题猜日期、用采集时间代替发表时间、把素材更新时间当发表时间均不允许。旧短链接与合集长链接在标题及发表时间一致时复用原 slug，避免同一文章出现两页。

正文保留文字、层级、列表、代码和图片，移除脚本、事件处理器与内联排版。微信的音视频、小程序卡片等互动内容需通过原文查看；当前图片转换为 WebP 静态资源，动画图片不保证保留动画。迁移不表示重新核实原文的技术结论。

网络、图片或校验失败不会覆盖文章数据文件；可能留下已验证但未引用的图片。重复导入无内容变化时不修改数据文件。当前是增量归档，原文之后隐藏或删除不会自动移除本站副本；发现这类变化后需明确复核并同步下架。

## 更新方式与边界

用户以后可以提供新文章链接，或要求继续检查已有公开合集。链接读取由本次交互式工作执行，未开启全天候后台抓取；GitHub Actions 只在提交或手动触发时部署已归档内容。

已移除之前预留的每小时官方接口检查和部署时取数步骤。无需为这条流程配置 IP 白名单、固定 IP runner 或微信密钥。未开发、未安装同步插件。

## 网站公开接口

GET `/api/articles.json` 是构建时生成的公开文章索引，包含标题、摘要、作者、日期、封面、原文链接与本站路径，不包含密钥。文章页面支持无 JavaScript 阅读。

GET `/api/wechat-source.json` 返回本次公开合集的覆盖范围和已导入来源，便于区分公开读取和账号后台数据。不会提供粉丝、阅读量、草稿、登录状态等非公开数据。
